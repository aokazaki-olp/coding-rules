# obsidian-config スキル

## 目的

AI が Obsidian vault 内、または Obsidian で後から開ける Markdown 保存先にファイルを読み書きする前に、**保存先・ファイル名・vault パスを一貫して決定する**ための基盤スキル。

Obsidian vault 内、または Obsidian で後から開ける Markdown 保存先にファイルを読み書きする前に、必ずこのスキルの手順で解決する。

ノート本文の整形、ログ本文の生成、Canvas 作成、Bases 作成などは行わない。それらは別の Obsidian 操作スキルに委ねる。

**パス/フォルダの解決は読み取り・書き込みで共用**する。ファイル名生成・衝突連番・フォルダ作成は**書き込み時のみ**。読み取り時は、対象ファイルは呼び出し側が指定し、本スキルはフォルダ/パス解決だけを行う（新規ファイル名生成・衝突連番・フォルダ作成はしない。対象が存在しなければその旨を報告する）。

---

## 基本方針

- **Obsidian のインストールに依存しない**（これが第一目的）。Obsidian が無い環境でも、後で Obsidian で開けば有効な Markdown を生成できる
- Obsidian CLI ツールには依存しない
- ファイルの直接読み書きで完結させる
- Obsidian プラグインとは疎結合を維持する。Templater・Dataview などのプラグイン構文は使わない
- **AI は日時を暗算しない**。実行環境で取得できる手段で、`timezone` を指定して取得する（後述）
- タイトル・パスなどの値は AI が直接計算して書く
- 既存ファイルを上書きしない
- 必要なフォルダが存在しない場合は作成する（書き込み時のみ）
- このスキルは解決のための基盤であり、ノート内容の設計は行わない

### obsidian-cli との棲み分け

- **本スキル（直接ファイル R/W）**: Obsidian 未インストール・未起動でも動く。既定はこちら。
- **obsidian-cli スキル**: ライブの Obsidian インスタンスを操作する必要がある場合のみ。Obsidian のインストールと起動が前提。

---

## プロジェクトルートの定義

AI エージェントが作業している現在のワーキングディレクトリを指す。ユーザーまたは実行環境が明示的に指定している場合はそれを優先する。

---

## 設定ファイルの読み込み

Obsidian 操作の前に、プロジェクトルートの `obsidian.json` を読む。以下が**デフォルト設定**であり、`obsidian.json` が存在しない場合もこの設定で動作する。

```json
{
  "vault_path": "obsidian",
  "folders": {
    "daily":   "ai/daily",
    "notes":   "ai/notes",
    "reviews": "ai/reviews",
    "logs":    "ai/logs"
  },
  "default_folder": "daily",
  "date_format": "YYYY-MM-DD",
  "time_format": "HHmm",
  "title_max_chars": 20,
  "timezone": "Asia/Tokyo"
}
```

### 各フィールドの意味

| フィールド | 意味 | デフォルト |
|---|---|---|
| `vault_path` | vault のルートパス | `obsidian` |
| `folders` | 目的キー → vault 内相対パス のマップ | `{ "daily": "ai/daily", "notes": "ai/notes", "reviews": "ai/reviews", "logs": "ai/logs" }` |
| `default_folder` | purpose 未指定時に使う `folders` のキー | `daily` |
| `date_format` | ファイル名の日付フォーマット | `YYYY-MM-DD` |
| `time_format` | ファイル名の時刻フォーマット（untitled 時のみ使用） | `HHmm` |
| `title_max_chars` | ファイル名に付けるタイトルの最大文字数 | `20` |
| `timezone` | 日時取得に使うタイムゾーン | `Asia/Tokyo` |

---

## 設定ファイルが使えない場合

`obsidian.json` が存在しない・パースできない・一部フィールドが欠ける場合は、上記デフォルト値で補完する。

- 存在しない → すべてデフォルト
- JSON としてパース不能 → すべてデフォルトで続行し、**完了報告時に警告**する
- 一部フィールド欠落 → そのフィールドだけデフォルト補完

---

## 設定値の補正ルール

型が想定と異なるフィールドは、そのフィールドだけデフォルトを使う。

- `vault_path`: **非空の**文字列のみ有効（空・空白のみなら既定 `obsidian`）
- `date_format` / `time_format` / `timezone`: 文字列のみ有効
- `title_max_chars`: 正の整数のみ有効
- `folders`: 「文字列キー → 文字列パス」のオブジェクトのみ有効。個々の値が不正なエントリはそのエントリを無効化する。**有効エントリが1つも無く空マップになった場合は既定 map（`daily`=`ai/daily` / `notes`=`ai/notes` / `reviews`=`ai/reviews` / `logs`=`ai/logs`）を使う**
- `default_folder`: `folders` に存在するキーのみ有効。不正なら `daily`（無ければ有効な `folders` の先頭）。無効化されたエントリのキーは「存在しない」として扱う

### フォルダパスの制約（`folders` の各値・および明示指定パス）

vault 内の相対パスのみ許可する。以下は不正としてそのエントリを無効化する（明示指定時はユーザーに確認）。

- 絶対パス
- `..` によって vault 外へ出るパス
- 空文字
- いずれかのパスセグメントがファイル名禁止文字（`: * ? " < > |` 等）を含む、または禁止文字だけで構成されるパス（例 `ai/no:tes` は不正）
- パスセグメントが `.obsidian` に一致するパス（Obsidian 設定ディレクトリ。`.obsidian` 自体および `.obsidian/…` 配下。設定破壊防止）

`timezone` が未指定・空・不正なら `Asia/Tokyo`。`date_format` / `time_format` が空・未対応の英字トークンを含む・ファイル名として不正な結果になる場合はデフォルト（`YYYY-MM-DD` / `HHmm`）を使う（詳細は「日時の取得」のトークン節）。

---

## 保存先フォルダの解決（目的別）

「どの purpose か」は意味判断であり、**呼び出し側（ユーザー意図を汲んだエージェント）が決める**。本スキルはマップに従って解決・検証するだけ。

1. 呼び出し側が **purpose キー**（例 `notes` / `reviews` / `daily`）を渡した → `folders[キー]` の相対パスを使う。キーが `folders` に無ければ（無効化されたエントリのキーも「無い」扱い）ユーザーに確認
2. 呼び出し側が **明示の vault 相対パス**を渡した → 上記フォルダ制約で検証して使う
3. 何も渡されない → `folders[default_folder]` を使う

purpose はユーザーの依頼から推せることが多い（「メモしといて」→ `notes` / 「レビュー結果を記録」→ `reviews` / 「作業の記録を残して」→ `logs`）。推せないときのみ `default_folder` を使うか確認する。

---

## パス解決

1. `vault_path` が定義されていればそれを使う。未定義なら `obsidian`
2. `vault_path` を実際のパスに解決する。絶対判定 = `/` で始まる（Unix）または ドライブレター（`C:\` 等）・`\\` で始まる（Windows）→ そのまま使用。いずれでもなければ相対としてプロジェクトルートから解決
3. 末尾の `/` `\` は結合前に取り除いて正規化する（`obsidian/` → `obsidian`）
4. 保存先を `<vault_path>/<解決したフォルダ>/` として決定する
5. 必要フォルダの存在確認と作成は下記に従う

---

## フォルダ作成の共通ルール

**書き込み時のみ**、存在しなければ親を含めて作成する（`mkdir -p` 相当。読み取り時はフォルダ作成しない）:

- `<vault_path>/`
- `<vault_path>/<解決したフォルダ>/`

作成は1回だけ試みる。権限エラー・パス不正・I/O エラー等で失敗したら、リトライせず中断してユーザーに確認する。

---

## vault 状態の判定

```text
<vault_path>/.obsidian/ が存在する   → vault内モード
<vault_path>/.obsidian/ が存在しない → vault未確認モード
```

どちらのモードでも `<vault_path>/<解決したフォルダ>/` に Markdown を保存する。違いは完了報告のみ（後述）。vault 未確認でも保存するのは、**Obsidian 非在でも成立する**という第一目的による。

---

## 日時の取得

**AI は日時を暗算しない**（現在時刻、特に時刻は AI のコンテキストに無く推測が不正確になる）。実行環境で取得できる手段を使い、`timezone`（IANA 名）を必ず適用して取得する。取得手段は OS 依存でよい:

```text
優先順（使えるものを上から）:
1. python（推奨・IANA を直接使える。要 Python 3.9+、古ければ pytz）:
   python3 -c "from datetime import datetime; from zoneinfo import ZoneInfo; print(datetime.now(ZoneInfo('Asia/Tokyo')).strftime('%Y-%m-%d-%H%M'))"
2. Unix / macOS / WSL / Git Bash :
   TZ="Asia/Tokyo" date +%Y-%m-%d-%H%M
3. node : `Intl.DateTimeFormat('en-CA',{timeZone:'Asia/Tokyo',year:'numeric',month:'2-digit',day:'2-digit',hour:'2-digit',minute:'2-digit',hour12:false}).formatToParts()` の各 type（year/month/day/hour/minute）から成分を取得（成分単位で扱う）
4. PowerShell : ConvertTimeBySystemTimeZoneId は Windows ID を要求するため IANA（Asia/Tokyo）→ Windows ID（Tokyo Standard Time）変換が要る（ICU 対応環境なら IANA 可）
5. いずれも使えなければ中断（下記）。※ 最初に成功した手段で確定し、全手段が失敗した場合のみ中断
```

- **生の出力書式に依存せず**、年月日時分の各成分を下記トークンへ割り当てて `date_format` / `time_format` に整形する（例: `2026-07-12` → `YYYY=2026, MM=07, DD=12` ／ `1430` → `HH=14, mm=30`）
- 必要なのは **日付は常に**、**時刻は untitled 確定後のみ**（→「ファイル名の生成」の処理順序に従う）
- `timezone` 未指定時は `Asia/Tokyo`（JST・UTC+9）
- **どの手段も使えない場合は、暗算せず中断してユーザーに確認する**。`timezone` が非 IANA 等で無効な場合、python / PowerShell はエラーになるが Unix `date` / node は黙って UTC へフォールバックしうる（IANA 妥当性の確認は python 経路が確実）。無効な `timezone` は既定 `Asia/Tokyo` で1回再取得し、それでも失敗したときのみ中断する

### フォーマットトークン（意味の定義）

`date_format` は日付トークンのみ、`time_format` は時刻トークンのみで構成する。取得結果をこのトークンに割り当てて整形する。大文字小文字を区別する（`MM`=月 / `mm`=分 を混同しない）。

```text
YYYY → 4桁年（2026）   MM → 2桁月（05）   DD → 2桁日（06）
HH   → 2桁時（14, 24h）   mm → 2桁分（30）
```

トークン（`YYYY` / `MM` / `DD` / `HH` / `mm`）以外の**英字**を含むフォーマットは無効とし、デフォルト（`YYYY-MM-DD` / `HHmm`）に戻す（例: `HHmmss` の `ss` は未対応 → 無効）。ハイフン等の非英字リテラルはそのまま含める。

## ファイル名の生成（ハイブリッド）

タイトルの有無で形式を分ける。通常 AI は保存時にタイトルを付けるため、既定は titled 形式になる。

```text
title あり → {date_format} + "-" + {サニタイズ済タイトル} + ".md"
              例: 2026-05-06-クロスAIエージェント設計.md   （時刻は付けない）
title なし → {date_format} + "-" + {time_format} + ".md"
              例: 2026-05-06-1430.md                       （時刻が一意キー兼時系列）
```

- titled は日付のみで時刻を含めない（タイトルが識別子。時刻はノイズ）
- untitled は時刻が一意性と日内の時系列順を担う

**処理順序（重要）**: ① タイトルをサニタイズ → ② titled/untitled を確定（タイトルが提供され、サニタイズ後も非空 → titled。未提供・空・サニタイズ後に空 → untitled）→ ③ 確定に応じて必要な日時を取得（titled = 日付のみ / untitled = 日付＋時刻）→ ④ ファイル名生成 → ⑤ 衝突連番。**日時取得を命名より先に済ませないこと**（先に取得すると untitled への転落時に時刻未取得となり「暗算禁止」と衝突する）。

### タイトルの文字数

タイトルは `title_max_chars` 文字以内。数える単位は**書記素クラスタ**（日本語1文字・英数字1文字・絵文字は原則1文字。ZWJ 連結・肌色修飾も1書記素）。厳密な書記素分割が難しい環境では、最善努力で連結絵文字の境界を壊さないようにする。

---

## ファイル名サニタイズ

タイトルをファイル名に含める場合の処理順:

1. 改行（LF/CR）・タブ・その他制御文字（<0x20）をスペースに変換
2. ファイル名禁止文字 `/ \ : * ? " < > |` を `-` に置換
3. 連続スペースを1つにまとめる。連続ハイフンも1つにまとめる
4. 前後の空白・ハイフン・ドット・アンダースコアを削除
5. 結果が空、または無意味文字（空白・ハイフン・ドット・アンダースコア）のみで意味のある文字が無い場合は、タイトルなし（untitled）として扱う
6. `title_max_chars`（書記素クラスタ単位で数える）を超える場合は先頭から書記素境界で切り詰める（末尾に `…` は付けない）
7. 切り詰めで末尾に空白・ハイフン・ドット・アンダースコアが残ったら再度削除する

連番サフィックスは上記の後に付ける。日本語・絵文字・英数字は使用可。

---

## ファイル名衝突時のルール

生成予定のファイルが既に存在する場合、上書きせず末尾に連番を付ける。

```text
2026-05-06-obsidian設定検討.md
2026-05-06-obsidian設定検討-2.md
2026-05-06-obsidian設定検討-3.md
```

untitled の場合も同様（`{date}-{time}` の末尾に連番）:

```text
2026-05-06-1430.md
2026-05-06-1430-2.md
```

連番は `-2` から始める。`-99` まで空きが無ければ、通常運用を超えた異常状態とみなし、中断してユーザーに確認する。

---

## 書き込み後の報告ルール

書き込み後、保存パスを簡潔に報告する。

```text
保存しました: <保存したファイルパス>
```

中断時は保存完了と報告せず、失敗理由と確認したい内容を報告する。

### 警告として報告する（該当時のみ）

- vault 未確認モードだった（`.obsidian/` 未検出だが Markdown は生成済み。後で `<vault_path>` を vault として開けば確認できる旨を伝える）
- `obsidian.json` がパース不能でデフォルトを使った
- フォルダ作成に失敗して中断した
- 日時取得手段が全滅して中断した
- `-99` まで空きが無く中断した
- 明示指定フォルダ／purpose キーが不正で確認が必要になった

### 情報レベル（通常は報告しない）

- `obsidian.json` 不在／一部欠落／型不正をデフォルト補完した
- 保存先フォルダを新規作成した
- 同名衝突で連番を付けた

ユーザーが経緯や詳細ログを求めた場合のみ、短く報告する。

---

## Gotchas（既知の注意点）

- **第一目的は Obsidian インストール非依存**。Obsidian CLI・プラグイン（Templater/Dataview）に依存しない
- **AI は日時を暗算しない**。環境の手段で timezone 指定取得。titled は日付のみ・untitled は日付+時刻
- ファイル名は**ハイブリッド**: titled=`{date}-{title}` / untitled=`{date}-{time}`
- 既存ファイルは上書きしない（衝突は `-2..-99` 連番、超過で中断確認）
- フォルダは**目的別マップ**。purpose は呼び出し側が決め、本スキルは解決・検証のみ。パスは vault 内相対のみ
- `.obsidian/` が無くても Markdown は生成する（vault 未確認モードは報告で補足）
- タイトルが空ならハイブリッドの untitled 形式（`{date}-{time}.md`）に落ちる。titled で末尾ハイフンは作らない
- **処理順序厳守**: サニタイズ → titled/untitled 確定 → 日時取得。日時を先取りしない（暗算禁止と衝突するため）
- 日時取得手段が全滅したら暗算せず**中断・確認**する
- **read はフォルダ/パス解決のみ**（ファイル名生成・衝突連番・フォルダ作成をしない）
- 未対応の英字トークンを含む `date_format` / `time_format` は既定に戻す（黙って素通りさせない）
- `MM`（月）と `mm`（分）を混同しない
